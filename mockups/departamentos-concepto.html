Un registro nuevo: DEPARTMENTS

Al lado de BRAIN_MODULES defines qué módulos ve cada área y qué rol la abre. La navegación lee de aquí — cero código nuevo por módulo.

export const DEPARTMENTS = [
  {
    id: 'pm',
    name: 'Project Manager',
    roles: ['project_manager'],
    modules: ['profile','tasks','ropre',
              'meetings','programs','team'],
  },
  {
    id: 'finanzas',
    name: 'Planeación & Finanzas',
    roles: ['finanzas'],
    modules: ['planning','projections','metrics'],
  },
  {
    id: 'content',
    name: 'Content Manager',
    roles: ['content_manager'],
    modules: ['content','profile','tasks','team'],
  },
]

// El nav ya no muestra 10 módulos sueltos;
// muestra los del área activa. Un módulo
// puede estar en varias áreas — es el mismo.

El recorrido del usuario

El rol define en qué área aterriza. Puede cambiar de área si tiene permiso.

login→se lee su rol
rol→aterriza en su departamento
departamento→ve solo sus módulos
módulo→el mismo dato de siempre

Los permisos (RLS) siguen siendo la seguridad real: el departamento decide qué se ve; RLS decide qué se puede tocar (editor / viewer).
